## 3. Getting started on a fresh machine

### 3.1 Prerequisites
- Python 3.8+ (project developed on 3.9, works on newer).
- Internet access to `api.openai.com` or `openrouter.ai` (no MITM proxy).

### 3.2 Steps

```powershell
# 1. Get the code onto the personal machine (git clone, USB, OneDrive, etc.)
cd LLM-PoweredFileSystemAssistant

# 2. Install dependencies
py -m pip install -r requirements.txt

# 3. Regenerate the PDF/DOCX sample resumes (idempotent)
py scripts\generate_sample_resumes.py

# 4. Configure .env
#    - Open .env
#    - Replace OPENAI_API_KEY with a FRESH key (see §5)
#    - Keep OPENAI_BASE_URL / OPENAI_MODEL as they are for OpenRouter,
#      or comment both out and use "sk-..." for native OpenAI.

# 5. Verify Part A
py tests\test_fs_tools.py                # expect 10/10 passed

# 6. Verify Part B without API calls
py llm_file_assistant.py --dry-run       # prints tool schemas

# 7. Live query (uses the API)
py llm_file_assistant.py "list all files in sample_data"
py llm_file_assistant.py "find resumes mentioning Python in sample_data"
py llm_file_assistant.py "create a summary file for sample_data/resume_michael_chen.pdf at output/summary_michael.txt"
```

### 3.3 Interactive REPL

```powershell
py llm_file_assistant.py
```

Type queries at the `you>` prompt. Type `exit` or Ctrl-C to quit.
Conversation history is preserved across turns in the same session.

## 6. Corporate machine — SSL issue (for reference)

If you ever need to run on the corporate machine, the OpenAI SDK's `httpx`
client fails TLS verification because `certifi`'s bundle doesn't include
the corporate MITM proxy's root CA. Two fixes:

**Option A — `truststore` (recommended)**
```powershell
py -m pip install truststore
```
Then add at the top of `llm_file_assistant.py`:
```python
import truststore
truststore.inject_into_ssl()
```
This makes httpx use the Windows cert store (same store pip already trusts).

**Option B — point at a CA bundle**
Get the corporate root CA `.pem` from IT and set:
```powershell
$env:SSL_CERT_FILE = "C:\path\to\corp-root.pem"
$env:REQUESTS_CA_BUNDLE = "C:\path\to\corp-root.pem"
```

Never disable TLS verification — that's both insecure and a corporate
policy violation.
